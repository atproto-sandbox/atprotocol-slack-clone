## 1. Architectural Overview

### 1.1 Atmospheric Group Model (`1 Group == 1 DID`)

- **Group Identity & Signed Public Repo:** Each group is its own `did:plc:...` account publishing `rotationKeys`, `#atproto` (signing key), `#atproto_kem` (P-256 HPKE key), and `#atproto_pds` (`serviceEndpoint: groupHostOrigin`, type `AtprotoPersonalDataServer` — never the removed `#atproto_space_host` service ID, per `alpha-migrations/prompt-10-22-26.md:113-120` and `spaceHostAud(did) === "${did}#atproto_pds"`). Its signed `@atproto/repo` MST public repository optionally publishes `group.opensocial.declaration/self` (`proposal.md:133`: published by Flock when `publicMeta === true`, and optional for nondiscoverable or migrated third-party OpenSocial groups) pointing to `at://<groupDid>/space/group.opensocial.meta/self`.
- **Core Spaces & Flat Union RBAC (`group.opensocial.policy`):** Each group hosts two non-deletable core spaces — `group.opensocial.meta/self` (`profile`, `rule`, `labeler`, `com.atproto.label.record`) and `group.opensocial.members/self` (`role`, `membership`, member-authored `acceptance`, host-maintained `space` modality index, account `com.atproto.label.record`) — plus modality spaces (`new.flock.workspace/self`, `new.flock.inbox/self`, `new.flock.channel/<skey>`, `new.flock.app.inbox/<appSkey>`, `new.flock.ext.tasks/<tasksSkey>`). Every space's `group.opensocial.policy` grants `{ role, read, write, scopes }` per role, `publicRead`, and `unlisted`, and is always auto-published as `com.atproto.space.policy/self`. Losing `write` on any space atomically evicts the member from that space's writer set (`removeWriter` + `notifySpaceUpdate` `com.atproto.space.defs#repoRemoved`).
- **Two-Sided Group Host OAuth (`prompt=create` & Live `effectiveMemberPermissions` Narrowing):** The Group Host is an ATProto OAuth 2.1 Authorization Server that authenticates users via standard ATProto OAuth against **their own personal PDS**, checks their current roles and space policies in the group, enforces `assignable` and scope/access anti-escalation on every write using `@atproto/oauth-scopes`, and dynamically narrows every group-DID session on every request to what the authorizing user's live `effectiveMemberPermissions` (`role.scopes` ∪ space-clamped `policy.grants[].scopes`) currently grant.
- **Cross-PDS Invitations (`group.opensocial.invites/self`):** On sign-in / first discovery (`WorkspaceClient.ensureInvitesSpace()`, §4.2), each user's app idempotently provisions `at://<userDid>/space/group.opensocial.invites/self` (`com.atproto.memberspace.policy` with `{ publicRead: false, publicWrite: true }` and zero members, `proposal.md:155`) on their personal PDS before registering `notify` or reading invites. Inviting groups write `group.opensocial.invite/<tid>` into `<groupDid>`'s own repo inside the invitee's `invites` space and track `notifyRepoUpdate` delivery (`pending` / `delivered` / `failed`); invitees discover pending invitations in-app and redeem them via `group.opensocial.requestJoin`, while deleting the `invite` record revokes it.
- **In-Space Moderation:** Members report records or accounts via `group.opensocial.createReport`; moderators review `listModSubjects` / `getModSubjectHistory` / `resolveModSubject` and publish `com.atproto.label.record` (`!takedown`, `!hide`, custom `labeler` values) in `<groupDid>`'s repo inside the subject's space. Per pinned Spaces (`alpha-migrations/prompt-11-12-26.md:234-236`), `!takedown` is a syncer/app convention (host-side record omission would break LtHash commits), enforced identically across `@flock/client`, `@flock/reader`, `apps/web`, `apps/echo-bot`, and `apps/webhooks`.

### 1.2 Complementary Session Modes (`proposal.md:95-99`)

1. **Per-User Group-DID Sessions (`GroupBrowserOAuthClient` in `apps/web/src/browser/group-session.ts` & `GroupClient` in `packages/client/src/group-client.ts`):**
   - Built directly on the base `OAuthClient` (re-exported by `@atproto/oauth-client-browser`) — **never** `BrowserOAuthClient` (which hardcodes `BrowserOAuthDatabase('@atproto-oauth-client')`, strips custom `sessionStore`/`stateStore`, and overwrites `localStorage['@@atproto/oauth-client-browser(sub)']`).
   - Uses a dedicated browser `RuntimeImplementation` (`@atproto/jwk-webcrypto` `WebcryptoKey.generate(['ES256'])`, `crypto.getRandomValues`, `crypto.subtle.digest('SHA-256')`, and `navigator.locks` under `flock-group-lock:${viewerDid}:*`) and an isolated IndexedDB database named `flock-group-oauth:${viewerDid}` (`sessions` keyed by `groupDid`, `states` keyed by `state`, `dpopNonces`), served via `/oauth/group-client-metadata.json` and `/oauth/group-callback`. `signOutAccount(viewerDid)` revokes active group sessions and calls `indexedDB.deleteDatabase("flock-group-oauth:" + viewerDid)`.
   - Used by **moderators** (`moderator` role), **profile editors** (`authManageProfile`), **admins** (`authManageGroup`), and **independent clients** for direct browser-to-Group-Host moderation, join-request review, rules, profile edits, invites, reactivation, and step-up confirmation, with the **Group Host** enforcing live roles and `assignable`.

2. **Shared Application Session on Flock Operator (`proposal.md:98`, `apps/operator`):**
   - Authorized at group creation (`prompt=create` on `AppConfig.groupHostUrl` authenticating creator at their personal PDS) and reauthorizable by **any active effective human admin** via their own personal PDS.
   - Powers: (a) **1-webhook-per-space `notify` registration** (`registrations.ts`, keyed on Operator by `PRIMARY KEY (service_ref, space_uri)` reusing one stable token per space), (b) **crash-safe multi-space modality orchestration** (`createChannel`, `transitionChannel`, `archiveChannel`, `decideJoinRequest` [preserved for `new.flock.inbox/self` private-channel join requests], `decideGroupJoinRequest` [new distinct kind for OpenSocial group `approval` admission], `installApp`, `updateAppAccess`, `uninstallApp`, `enableExtension`, `disableExtension`), and (c) **member self-service private-channel leave** (`leaveChannel`, removing only `channel-<skey>` from `membership/<callerDid>`).
   - **Confused-deputy defense, canonical `effectiveMemberPermissions`, versioned SQLite upgrade (`OPERATION_TAKEOVER_MIGRATION = 4`) & deterministic demoted-actor recovery (`proposal.md:52-55,59,98,195`, `apps/operator/src/lib/db.ts`, `operations.ts`, `journal.ts`):** Every journaled operation persists `actor` (`ownerDid`, immutable `PRIMARY KEY (workspace, actor, operation_id)` and `operationRequestHash` owner). **`apps/operator/src/lib/db.ts` adds versioned migration `OPERATION_TAKEOVER_MIGRATION = 4` in `schema_migration`:** inside `BEGIN IMMEDIATE ... COMMIT`, if `schema_migration` lacks `version = 4`, rebuilds existing `operation` via `operation_r13_rebuild` (`DROP TABLE operation; ALTER TABLE operation_r13_rebuild RENAME TO operation` + recreating `operation_status`, `operation_workspace_recovery`, and `operation_workspace_stalled`) to widen `CHECK (state IN ('queued','running','pending','completed','failed','paused','aborted_actor_revoked'))` and add nullable `taken_over_by TEXT` (`NULL` backfilled on upgraded rows, tested in `apps/operator/src/lib/db.test.ts` against a seeded R12 6-state DB!). Before initial admission, before **each step**, and before **every crash-recovery resume**, Operator re-reads live `group.opensocial.members/self` (`role/*` and `membership/*` — **never gating Operator authorization on personal-PDS `acceptance/self`, per `proposal.md:59,195` where authorization derives strictly from `membership`, `role`, `policy`, and `assignable` while `acceptance/self` gates roster display & client discovery, so `createWorkspace` succeeds cleanly before the creator writes `acceptance/self`!**) **plus every non-deleted space's `com.atproto.space.policy/self` (`group.opensocial.policy`)** and re-verifies live human membership (`actor !== groupDid && !knownAppSubjects.has(actor)`), **required canonical effective permissions (`effectiveMemberPermissions` — unioning assigned `role.scopes` AND every space's matching `policy.grants[].scopes` clamped to that space, `proposal.md:52-55`)**, and `assignable` coverage over every target role/member. If the admin who authorized the shared session is demoted or ejected, Group Host immediately narrows/refuses that session (`403`), triggering `AuthorityReauthorizationRequiredError` so an active effective human admin reauthorizes via their own personal PDS. **When `resumeRecoverableOperations` encounters a pending operation whose original `ownerDid = row.actor` was subsequently demoted or ejected (preventing permanent workspace wedging!):** (1) if `kind.actor === "member"` (`leaveChannel`) and `ownerDid` is already ejected or already lacks `channel-<skey>`, marks `completed` (`operationSatisfiedByState`); (2) if `row.completedSteps.length === 0` (zero side effects committed), updates `(workspace, ownerDid, operation_id)` to terminal `state = 'aborted_actor_revoked'` (`operationAbortedActorRevoked`); (3) if `row.completedSteps.length >= 1` (partial durable state exists), verifies that the **recovering human admin (`executorActor.did`)** independently holds live `effectiveMemberPermissions` + `assignable` coverage for `row.request` (`403` until a sufficiently privileged admin recovers it), passes `takeoverBy: executorActor` into `runJournaledOperation` (which keeps `(workspace, ownerDid, operation_id)` as the journal row key & `requestHash` owner while setting `operation.taken_over_by = executorActor.did`, exposing `takenOverBy?: string` on `OperationView`, and recording `operationAdminTakeover`, all subsequent step events, and `operationCompleted` in `audit_event` under `audit_event.actor = executorActor.did`!), and replays the remaining idempotent steps to completion!
