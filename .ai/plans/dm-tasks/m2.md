# M2 — Isomorphic protocol core

Read `common.md` first. Goal: the browser DM client (M3/M4) and the existing server channel code must share **one** audited implementation of DPoP proofs, space-credential exchange, XRPC, record paging, keys, and record validation. The server keeps its SSRF-guarded fetch and OAuth session. The browser will supply its own. No behavior change for existing server features.

## Allowed dependencies
- `@noble/hashes` pinned at exactly `1.8.0` (already in the lockfile tree). It's for a synchronous SHA-256 that works in both Node and browsers.
- `@atproto/jwk` (the `Key` interface), only if it isn't already reachable. Pin it to the version already in the lockfile.

## Tasks
1. **`src/protocol/keys.ts` → isomorphic.** Replace `node:crypto` with `@noble/hashes/sha256` for `stableHash`, and with `crypto.getRandomValues` (global in Node 22 and browsers) for `randomInt`. Keep outputs **byte-identical**: add a test with fixed known vectors computed with the current implementation *before* you change it, for `stableHash`, `recordKeyHash`, `reactionRecordKey`, `requestRecordKey` and `subjectKey`.
2. **`src/atproto/dpop.ts` → isomorphic.** Replace `createHash`/`randomBytes` with `@noble/hashes` (or `crypto.subtle`, which would make the function async; it already is) and `crypto.getRandomValues`. Type the key parameter as a minimal structural interface: `{ bareJwk: ...; algorithms: readonly string[]; createJwt(header, payload): Promise<string> }`, which both `JoseKey` and `@atproto/jwk-webcrypto`'s `WebcryptoKey` satisfy. Add a test that a proof verifies with `jose` (`jwtVerify` against the embedded JWK) and that `ath` equals `base64url(sha256(credential))`.
3. **`src/atproto/space-credential.ts` → isomorphic core + server adapter.**
   - Create `src/atproto/space-credential-core.ts` with `SpaceCredential`, `SpaceCredentialError`, `exchangeSpaceCredential` and `mintSpaceCredentialWith(deps, space)`. It takes injected deps `{ memberClient: AtprotoClient; resolvePds(did): Promise<string>; fetchEndpoint(request: Request): Promise<Response>; generateKey(): Promise<DpopKey> }` and has no Node or server imports.
   - Keep `src/atproto/space-credential.ts` as the thin server adapter, exporting the same `mintSpaceCredential(session, space)`, `SpaceCredential` and `SpaceCredentialError` names so no existing caller changes. It injects `sessionClient`, server `resolvePds`, `fetchValidatedEndpoint` and `JoseKey.generate(["ES256"])`.
   - Move the space-URI parser into `src/protocol/keys.ts` as `parseSpaceUri(uri): { authorityDid, type, skey } | null`, and reuse it in `notifications.ts` / `channel-sync.ts` wherever they hand-roll the same regex. Only do that where it's a pure refactor.
4. **Confirm `src/atproto/xrpc.ts`, `src/atproto/record-pages.ts`, `src/lib/bounded-json.ts`, `src/protocol/records.ts` and `src/atproto/valid-channel-messages.ts` have no Node/server imports** after task 1. Fix any that do.
5. **Lint boundary** in `eslint.config.mjs`: add a `no-restricted-imports` override for `src/dm/**` and for the isomorphic modules listed in tasks 1–4 (plus `space-credential-core.ts`). It forbids `node:*`, `@/lib/db`, `@/lib/config`, `@/auth/*`, `@/operator/*`, `@/workspaces/*`, `@atproto/oauth-client-node`, `undici`, and `@/atproto/identity`. Create `src/dm/index.ts` containing only `export {};` so the rule has a target. Prove the rule works by temporarily adding a forbidden import, confirming lint fails, then removing it (mention this in your final message; don't leave it in).
6. **No regressions.** Run `pnpm test`, `pnpm typecheck` and `pnpm lint`, and run `pnpm test:acceptance` against the pinned checkout (see `common.md`). The acceptance suite exercises the real server credential path end to end and must pass.

## Done when
All checks pass, including acceptance, the fixed hash vectors match, and the isomorphic modules import nothing server-only (the lint rule enforces this).
