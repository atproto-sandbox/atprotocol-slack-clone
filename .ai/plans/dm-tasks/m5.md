# M5 — DM user interface and real-time updates

Read `common.md` (you are running under OpenCode; the same rules apply) and the plan's §3.3–3.6 first. The browser runs the M4 `DmClient` using the M3 browser session. The server's only role is serving the page and a **content-free** change stream.

## Allowed dependency
`@atproto/jwk-webcrypto`, pinned exactly at the version already in the lockfile (0.3.4), for non-extractable DPoP keys (`WebcryptoKey.generate`).

## Browser wiring (all under `src/dm/`, isomorphic or browser-only; never server)
- **`browser-identity.ts`**: `resolvePds(did)` for `did:plc` (via `plcUrl` from `dmConfig`) and `did:web` (`/.well-known/did.json`). It reads the `#atproto_pds` service endpoint and requires `https:`, allowing `http:` only for loopback hosts when `dmConfig.loopback` is true. It uses `redirect: "error"`, bounded JSON (`readUpstreamJson`), and an in-memory cache with a 10-minute TTL. Also export `resolveHandle(did)` from the DID doc's `alsoKnownAs` (`at://handle`), used only for display.
- **`browser-store.ts`**: the `DmDeps.store` implementation, backed by `localStorage` under the prefix `dm:<did>:`, with every access in try/catch. When storage is unavailable, it falls back to in-memory state and says so in the UI.
- **`use-dm-client.ts`**: a React hook. It restores the M3 session for the signed-in DID and builds `DmClient` (`fetchEndpoint` = `fetch(request)` with `redirect:"error"`, `generateKey` = `WebcryptoKey.generate(["ES256"])`, non-extractable). It exposes `{ status: "disconnected" | "connecting" | "ready" | "error", client, error, connect, disconnect }`.

## Real-time (content-free)
- **Server:** add `src/app/api/notifications/dm/route.ts`, an SSE stream in the same style as `src/app/api/notifications/route.ts`.
  - It requires the server web session (`requireSession`) and accepts a single `space` param, which must parse as a DM inbox or DM conversation URI (strict parsers from `src/protocol/keys.ts`; reject anything else with 400).
  - It emits `change` events carrying only the cursor, from `space_notification` rows for that exact space.
  - It never reads records, never mints credentials, and never touches DM content. Add a comment noting that the space URI is unguessable (random `convKey`) and that the stream reveals only change timing.
- **Browser:**
  - After opening a conversation, call `client.watch(existing halves + own inbox, dmConfig.serviceRef)`. Add `serviceRef` to `dmConfig` from the existing `OPERATOR_SERVICE_REF` config; its `notifyWrite` route already accepts authority-signed notifications for any space.
  - Subscribe to the DM SSE stream for those spaces, and refresh on `change`, or on `error` only when `readyState === CLOSED`, matching the existing channel pattern.
  - Poll every 60 s as a fallback. Run `renotifyPending()` on connect and every minute.
