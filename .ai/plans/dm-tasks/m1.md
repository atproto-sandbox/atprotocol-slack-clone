# M1 — DM lexicons, keys, and record validation

Read `common.md` first. Scope: protocol definitions and pure validation only. No UI, no network code, no new dependencies.

## 1. Lexicons (new files under `lexicons/org/slack/dm/`)
Follow the exact JSON style of `lexicons/org/slack/inbox.json` (space type) and `lexicons/org/slack/channelReaction.json` (record).

| File / id | Kind | key | Fields |
|---|---|---|---|
| `inbox.json` / `org.slack.dm.inbox` | space | `literal:self` | collections `[org.slack.dm.request]`; description: personal DM request inbox, owner-read, owner-configured write policy |
| `conversation.json` / `org.slack.dm.conversation` | space | `tid` | collections `[org.slack.dm.header, org.slack.dm.message, org.slack.dm.reaction]`; description: one participant's half of a conversation, owner-only writes |
| `request.json` / `org.slack.dm.request` | record | `tid` | required `convKey` (string, format tid), `participants` (array of string format did, minLength 2, maxLength 100), `createdAt` (datetime) |
| `header.json` / `org.slack.dm.header` | record | `literal:self` | same three fields as request |
| `message.json` / `org.slack.dm.message` | record | `tid` | required `text` (string, maxLength 40000, maxGraphemes 10000), `createdAt`; optional `parent` (at-uri) |
| `reaction.json` / `org.slack.dm.reaction` | record | `any` | required `subject` (at-uri), `emoji` (1..32), `createdAt` |

Also add both space types to `lexicons/space-types.json`. For `org.slack.dm.inbox`, use `"writePolicy": "owner-configured"`; for the conversation, use `member-list` for both read and write, and `open` app access.

Validate every new lexicon with the pinned lexicon CLI the same way the existing ones were validated. Look at `scripts/codegen-lex.mjs` and `docs/protocol/atproto-spaces-pin.md` for how; the checkout is `../atproto-spaces-phase0`. Only regenerate `src/lexicons/api` if the script's inputs include `org.slack` record lexicons; they currently don't, so don't add them.

## 2. Keys (`src/protocol/keys.ts`, with tests in `keys.test.ts`)
- `DM_INBOX_SKEY = "self"`
- `dmInboxUri(ownerDid)` returns `at://<did>/space/org.slack.dm.inbox/self`
- `dmConversationUri(ownerDid, convKey)` returns `at://<did>/space/org.slack.dm.conversation/<convKey>`. It throws on an invalid DID or a non-TID `convKey`.
- `parseDmConversationUri(uri)` returns `{ ownerDid, convKey } | null`. Use a strict regex in the style of the existing parsers.
- `canonicalParticipants(dids)` returns the sorted, deduplicated DIDs. It throws unless there are 2–100 valid DIDs after deduplication.
- DM reactions reuse `reactionRecordKey(messageUri, emoji, authorDid)`.

## 3. Validation (`src/protocol/records.ts`, with tests in `records.test.ts`)
Extend `validateSpaceRecord` and `RecordContext` minimally. Read how channel messages and reactions are validated and mirror that shape. Rules, each with a failing-case test:

**`org.slack.dm.request`** (context: `spaceUri` = recipient's inbox, `repoDid` = sender, `rkey`)
- `spaceUri` must be a DM inbox URI. `rkey` must equal `convKey` and be a TID.
- `participants` must already be canonical (sorted, unique, 2–100 valid DIDs) and must include both the sender and the inbox owner. `createdAt` must be a valid datetime.

**`org.slack.dm.header`** (context: `spaceUri` = a conversation half)
- **`repoDid` must equal the half's owner DID.** M0 proved that non-owners can store records scoped to someone else's half, so this rule needs its own dedicated test.
- `rkey` must be `self`. `convKey` must equal the half's skey. `participants` must be canonical and include the owner.

**`org.slack.dm.message`**
- `repoDid` must equal the half's owner, and `rkey` must be a TID.
- `text` must be non-empty after trimming and at most 10,000 Unicode code points (the same rule as channel messages; reuse the helper if one exists).
- If present, `parent` must be an `org.slack.dm.message` record URI in *some* conversation half with the same `convKey`, whose owner is in the participant set. Take the participants from an optional `participants` field on the context; if it's absent, only enforce the `convKey` match. The parent must not be the message itself.

**`org.slack.dm.reaction`**
- `repoDid` must equal the half's owner.
- `subject` must be an `org.slack.dm.message` URI in a half with the same `convKey`, and `rkey` must equal `reactionRecordKey(subject, emoji, repoDid)`. The emoji must be 1–32 characters.

Also export `validateDmHeaderMatchesRequest(header, request)`, which returns true only when `convKey` and the participant arrays are identical.

## 4. Constants
Add `dmInbox: "org.slack.dm.inbox"` and `dmConversation: "org.slack.dm.conversation"` to `SLACK_SPACE_TYPES`, and add `dmRequest`, `dmHeader`, `dmMessage` and `dmReaction` to `SLACK_COLLECTIONS` in `src/auth/permission-sets.ts`. Don't add any scopes yet.

## 5. BDD spec
Write `features/direct-messages.feature` in the style of the existing `features/*.feature` files. Include scenarios for:
- enabling DMs;
- starting a 1:1 conversation (with local dedupe);
- starting a group conversation, the 100-participant boundary, and rejecting 101 participants;
- request discovery;
- the three request-policy modes, switching modes, and client-side filtering of writers tracked under an earlier policy;
- accepting by replying (auto-allowlist);
- reading and merging halves; ignoring records whose repo isn't the half owner; ignoring halves whose header doesn't match;
- edit and delete of your own messages; reactions;
- leaving (revoke) and delete-everything;
- a dropped request notification recovered by re-put backoff;
- cross-app recovery from your own PDS;
- the app server never holding DM scopes or DM content;
- conversation keys being random, never derived from participants.

## Done when
All of `common.md`'s checks pass, the new unit tests cover every rule above (happy path and each failure), and the lexicon CLI validates the six new lexicons.
