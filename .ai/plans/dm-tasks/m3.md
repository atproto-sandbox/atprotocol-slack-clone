# M3 — Browser-held DM OAuth session

Read `common.md` first. Goal: DM permissions exist **only** in a browser OAuth session (IndexedDB, non-extractable DPoP keys). The Next server session must never request, receive, or proxy DM scopes or DM content.

## Allowed dependency
`@atproto/oauth-client-browser` pinned at exactly `0.5.7`. It depends on `@atproto/oauth-client ^0.8.7`, matching the existing `oauth-client-node@0.5.7`, so the lockfile must contain a single `@atproto/oauth-client` version. Verify that and report it.

## Tasks
1. **Scopes, in `src/auth/permission-sets.ts`.**
   - Export `DM_BROWSER_SCOPES: readonly string[]`: `atproto` plus the minimum `space:` scopes for everything the plan's §3.3 flows do. These are: send/re-put/withdraw requests into any inbox (collection-restricted to `org.slack.dm.request`); create, read and update the policy and members of the user's own inbox; create, read, write records in, manage members of, and delete the user's own conversation halves; read other people's halves; and `read_self` for `listSpaces`.
   - Look up the exact grammar (`manage=` values, `authority=*`, `action=`) in `../atproto-spaces-phase0/packages/oauth/oauth-scopes/src`. Don't guess.
   - `memberSpaceScope` must throw for any `org.slack.dm.*` space type.
   - Add unit tests asserting that no server-side scope builder (`workspaceAuthorityScopes`, `memberSpaceScope` for every non-DM type, `WORKSPACE_DISCOVERY_SCOPE`, operator scopes, and whatever `src/auth/oauth.ts` requests at login) ever contains `org.slack.dm`.
2. **Prove the scopes on the pinned PDS.** Add a test to `protocol-tests/atproto/slack-dm-conformance.test.ts`, reusing its OAuth/WebCrypto helpers, that issues a token with **exactly** the `DM_BROWSER_SCOPES` strings (copy them verbatim, since that file runs inside the pinned checkout and can't import app code; add a comment naming the source constant). The test must show that the token can:
   - create its own inbox;
   - `updateSpace` its inbox policy;
   - `putMember`/`removeMember` on its own inbox and half;
   - create its own half;
   - write header, message and reaction records in its own half;
   - `deleteSpace` its own half;
   - write a request into another user's inbox;
   - get a delegation token for another user's half.

   It must also show the token **cannot** `putMember` on another user's half, **cannot** write a message record into another user's inbox, and **cannot** create a space of a non-DM type. Run it with the full DM suite and the two other Slack suites. All must pass.
3. **Client metadata.**
   - Add `src/app/oauth/dm-client-metadata.json/route.ts`, following the existing `src/app/oauth/client-metadata.json/route.ts` pattern. It returns a public client: `token_endpoint_auth_method: "none"`, `application_type: "web"`, `dpop_bound_access_tokens: true`, `redirect_uris: [<APP_URL>/dm/callback]`, and `scope` = `DM_BROWSER_SCOPES.join(" ")`.
   - For loopback development (http + loopback host, as `src/auth/oauth.ts` detects), use the atproto loopback client-id form (`http://localhost?redirect_uri=...&scope=...`, with the redirect on `127.0.0.1`), mirroring the server's loopback handling.
   - Put the pure metadata builder in `src/dm/client-metadata.ts`, taking `{ appUrl }` as input, with unit tests for both modes.
4. **Browser session, in `src/dm/browser-session.ts`.**
   - Dynamically import `@atproto/oauth-client-browser` so it never loads on the server.
   - Construct `BrowserOAuthClient` with the metadata from task 3, `plcDirectoryUrl` from config, and `allowHttp` only in loopback development. Handle resolution isn't needed because sign-in uses the DID the server session already knows.
   - Expose `connectDms(did)`, `restoreDmSession(expectedDid)` and `disconnectDms()`. If a restored or new session's DID doesn't equal the signed-in server DID, revoke it and throw, so one browser can never mix accounts.
   - The session's `fetchHandler` feeds an `AtprotoClient` (from `src/atproto/xrpc.ts`) for the M4 engine.
5. **Config reaches the client without new env vars.** `src/app/page.tsx` (server) passes a small `dmConfig` prop (`appUrl`, `plcUrl`, `loopback`) down to the client tree. Update `.env.example` only if a new variable is truly required; it shouldn't be.
6. **Callback page.** Add `src/app/dm/callback/page.tsx`, a client component that finishes the browser OAuth callback (the library's init/callback API), then navigates to `/`. On error, show the message using existing CSS classes (`form-error`), with no new styling.
7. **CSP, in `src/lib/security-headers.ts` (with tests).** The browser now talks to PDS and PLC hosts directly. `connect-src` becomes `'self' https:`, and adds `http://localhost:* http://127.0.0.1:*` only when `APP_URL` is loopback http. Keep every other directive unchanged. Update `security-headers.test.ts`.
8. **Minimal UI hook.** Add `src/app/ui/dm-connect.tsx`: a "Connect direct messages" button, or a connected state showing the DM session DID, placed in the sidebar below CHANNELS. Reuse the existing `section-label` / `sidebar-action` classes and add no CSS. Wire it into `sidebar.tsx`. M5 builds the real DM UI.

## Done when
All `common.md` checks pass, including all three pinned-PDS Slack suites (4 old + 5 DM tests) and `pnpm test:acceptance`. `pnpm build` succeeds, and the `@atproto/oauth-client-browser` code isn't in any server bundle. Check `.next/server` and report how you checked.
