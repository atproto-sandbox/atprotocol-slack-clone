# M4 — DM engine (`src/dm/`)

Read `common.md` and the plan's §3.1–3.6 first. The engine is isomorphic TypeScript: it runs in the browser (M5) and in Node tests and acceptance with injected transports. It must import only isomorphic modules. The M2 lint boundary enforces this.

## Shape
`src/dm/dm-client.ts` exports `class DmClient`, constructed with injected deps:
```ts
type DmDeps = {
  did: string;                                      // the signed-in user
  memberClient: AtprotoClient;                      // user's own PDS via their DM OAuth session
  resolvePds(did: string): Promise<string>;
  fetchEndpoint(request: Request): Promise<Response>;
  generateKey(): Promise<DpopKey>;                  // non-extractable WebCrypto key in the browser
  store: { get(key: string): Promise<string | null>; set(key: string, value: string): Promise<void>; delete(key: string): Promise<void> };  // per-user local state (backoff, hidden requests)
  now?: () => number;
};
```
Use `mintSpaceCredentialWith` from M2's `space-credential-core.ts`. Cache credentials per space in memory until 60 s before `expiresAt`. On `SpaceCredentialError`, drop the cached credential. Wherever the engine fans out, use `mapLimited(…, 8, …)`.

## Operations (each with unit tests against an in-memory fake; see Testing)
- **Inbox and request policy (§3.6):**
  - `getInbox()` returns `{ exists, mode: "everyone" | "allowlist" | "nobody", allowlist: string[] }`, derived from `simplespace.getSpace` plus `listBoundedMembers`: public write policy → everyone; memberList with write-members → allowlist; memberList without them → nobody.
  - `enableDms(mode, allowlist?)` creates the inbox if it's missing, then applies the mode.
  - `setRequestMode(mode)`, `allow(dids)` and `disallow(dids)` update the policy with `updateSpace` and set membership with `putMember` (`read:false, write:true`) or `removeMember`.
  - Put the mode ↔ policy mapping and its inverse in a pure function in `request-policy.ts`, with unit tests.
- **`listRequests()`:**
  - Enumerate the inbox writer set with `listBoundedRepos`, using the user's own inbox credential.
  - Fetch each writer's `org.slack.dm.request` records from **the writer's PDS**, using the inbox credential.
  - Validate each record with `validateSpaceRecord`.
  - Then **filter by the current mode**: in allowlist mode, keep only allowlisted senders; in nobody mode, keep none. This is mandatory because the M0 results show earlier writers stay listed.
  - Drop requests the user has hidden locally, and drop those for conversations the user already has a half for.
  - Return `{ convKey, participants, sender, createdAt, uri }`.
- **`listConversations()`:**
  - Take the user's own halves from `listSpaces({ type: "org.slack.dm.conversation" })` on their PDS (bounded paging) and read the header for each.
  - Add pending requests from `listRequests()`, marked `pending: true`.
  - Dedupe by `convKey`.
- **`startConversation(dids)`:**
  - Canonicalize the participant list, which must include the user and have 2–100 entries.
  - Local dedupe: if an existing own half has the identical participant set, return it.
  - Otherwise: `convKey = tidNow()` (never derived from participants); `createSpace` the half (memberList read and write, open app access); `putMember` each other participant with `read:true, write:false`; `putRecord` the header (`rkey: "self"`); then `putRecord` a request into each other participant's inbox.
  - Return per-participant delivery status: `delivered`, `noInbox` (their inbox's credential or `getSpace` says `SpaceNotFound`), or `failed` with a message.
- **`accept(request)`:** creates the user's own half with the request's `convKey` and participants, writes the header, and auto-allows the sender if in allowlist mode. `hideRequest(uri)` records the hide locally.
- **Messages:**
  - `send(convKey, text, parent?)`: create a TID-keyed record in the user's own half.
  - `edit(uri, text)`: `putRecord` with the same rkey; only for the user's own records.
  - `delete(uri)`
  - `react(subject, emoji)` / `unreact(subject, emoji)`: canonical rkey via `reactionRecordKey`.

  Validate locally with `validateSpaceRecord` before every write.
- **`readConversation(convKey, participants, { limit = 100, before? })`:**
  - For each participant (fan-out 8), mint a credential for their half at **their** PDS. `SpaceNotFound` means "hasn't replied yet", `SpaceDeleted` means "left", and `UserNotAuthorized` means "revoked you". Record these per-half statuses rather than failing.
  - Read each half's header and ignore the half if `validateDmHeaderMatchesRequest` fails against the participants.
  - K-way merge messages by TID across halves, paging each half's `listRecords` only as far as the merge window requires (mirror the idea behind the channel `fillLatest` in `src/workspaces/channel-sync.ts`).
  - Drop every record that fails `validateSpaceRecord`, which includes repo ≠ half owner.
  - Return `{ messages (newest first, ≤ limit), reactions for returned messages, halves: Record<ownerDid, status>, nextBefore? }`.
  - Put the merge in a pure `merge.ts` with unit tests: interleaving, uneven halves, the `before` cursor, and duplicates.
- **Leaving and deleting:** `leave(convKey)` removes every other participant from the user's own half and hides the conversation locally. `deleteEverything(convKey)` calls `deleteSpace` on the user's own half.
- **Re-notify (§3.3 step 7):** `renotifyPending()`. For each of the user's own conversations, participants with no half get the same request re-put, on a backoff of 1 min, 10 min, 1 h and 1 day, then it stops. State lives in `store`, keyed by `convKey + participant`. Keep the schedule as a pure function with unit tests.
- **Notifications:** `watch(spaces, serviceRef)` calls `com.atproto.space.registerNotify` for each given space, using that space's credential, and returns the expiry per space. The engine never depends on notifications for correctness.

## Testing
1. **Unit tests** (`src/dm/*.test.ts`) against `src/dm/testing/fake-pds.ts`: an in-memory multi-host fake that implements exactly the XRPC methods the engine calls, with member-list read/write enforcement, writer tracking that reproduces the M0 behaviors (earlier writers stay listed; untracked writes are stored but not listed), and the `SpaceNotFound`/`SpaceDeleted`/`UserNotAuthorized` errors. The fake is test-only; don't import it from production code.
2. **Backend acceptance on the real pinned PDS:** `protocol-tests/dm-acceptance.test.ts`, following the harness style of `protocol-tests/app-acceptance.test.ts` and reusing its fixture helpers where possible. It uses real `DmClient` instances whose `memberClient` is backed by each account's session on two PDS hosts. Flows:
   - 1:1: A starts, B sees the request in each policy mode (including the filtering of writers tracked under an earlier policy), B accepts, both exchange messages, edit/delete/react, the merge is correct, B leaves and A loses access, A deletes everything.
   - 3-person group.
   - A dropped notification recovered by `renotifyPending` (simulate the drop the way `protocol-tests/atproto/slack-inbox-conformance.test.ts` does).
   - **"Server off":** every DM flow above must run with no Next server started and with `DATABASE_PATH` pointing at a nonexistent directory. Assert the path is never created.

   Add the file to the `test:acceptance` script.
3. **Performance:** add `protocol-tests/dm-performance.test.ts` to `test:performance`: 100 participants across two hosts, 20,000 total messages spread across halves. It asserts `readConversation` for the latest 100 completes in ≤ 5 s and reports its timing. Run it once and report the numbers.

## Done when
All `common.md` checks pass, plus `pnpm test:acceptance` (existing and new), and one `dm-performance` run with its timing reported.
