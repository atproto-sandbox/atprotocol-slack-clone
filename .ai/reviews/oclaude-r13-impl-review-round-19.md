### Finding #1 — `abortMigration()` service-JWT fallback is unreachable due to missing RPC scope (Medium, blocking)

When the Target has already purged its `migration_session` and the Target-issued `accessJwt` has expired, `GroupClient.abortMigration()` correctly routes to `tryFallbackServiceAbort()`:

- `[packages/client/src/group-client.ts:1494](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/client/src/group-client.ts:1494)`–`[1509](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/client/src/group-client.ts:1509)` (called from `[1531](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/client/src/group-client.ts:1531)` / `[1556](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/client/src/group-client.ts:1556)`)
- It asks the Group's own host for `getServiceAuth` with `aud = targetServiceDid` and `lxm = "group.opensocial.abortMigration"` (`[group-client.ts:1497](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/client/src/group-client.ts:1497)`).

But the source Group Host gates this on `assertRpc({ aud, lxm })`:

- `[apps/group-host/src/migration.ts:4476](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/apps/group-host/src/migration.ts:4476)` requires both the OAuth session scope and live `effectiveMemberPermissions` to allow the RPC (the method is not in `PROTECTED_SERVICE_AUTH_METHODS`, so it passes to this check).

No scope grants that RPC:

- `groupAdminScopes()` only ever emits `rpc:*?aud=<groupDid>#atproto_pds` (wrong aud) plus `rpc?aud=*&lxm=com.atproto.server.createAccount&lxm=com.atproto.space.notifyCredentialsRevoked&lxm=com.atproto.space.notifyRepoUpdate` (`[packages/protocol/src/scopes.ts:233](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/protocol/src/scopes.ts:233)`–`[235](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/protocol/src/scopes.ts:235)`).
- The `group.opensocial.authManageGroup` permission set's RPC entry lists only `listJoinRequests`, `denyJoinRequest`, `listModSubjects`, `getModSubjectHistory`, `resolveModSubject` (`[packages/protocol/lexicons/group/opensocial/authManageGroup.json:51](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/protocol/lexicons/group/opensocial/authManageGroup.json:51)`), not `abortMigration`.
- The browser group admin session is authorized with `groupAdminScopes()` (no `groupDid`, so not even the concrete `aud=<groupDid>#atproto_pds` token), and the raw requested scope is stored verbatim as `approved_scope` (`[apps/web/src/browser/group-session.ts:663](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/apps/web/src/browser/group-session.ts:663)`; `[apps/group-host/src/oauth.ts:1980](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/apps/group-host/src/oauth.ts:1980)`).

Consequently `assertRpc` throws `ScopeMissingError` (403), `tryFallbackServiceAbort()` swallows it and returns `null` (`[group-client.ts:1506](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/client/src/group-client.ts:1506)`), and `abortMigration()` rethrows the refresh 401 without ever calling `requestSourceAbortMigration()`. The Source stays frozen until the 2-hour lease deadline/sweeper, which is exactly the Round 18 #1 failure mode for the expired-token case. `FakeNetwork` would behave the same (`requireGroupRpcPerm` → `narrowedGroupSessionPerms`, `[packages/testing/src/fake-network.ts:3048](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/testing/src/fake-network.ts:3048)`), so there is at least parity, but both fail closed.

The regression test masks this because it stubs `getServiceAuth` to return a fake token instead of exercising the host's scope check (`[packages/client/src/group-client.test.ts:1626](file:///Users/mikestaub/code/peapods/bluesky/atproto-spaces/atproto-slack-clone-r13-opensocial/packages/client/src/group-client.test.ts:1626)`); there is no GroupHost/FakeNetwork test that mints an abort service JWT through the real admin session.

Fix direction: grant the abort RPC to the admin role/session scope (e.g. add `lxm=group.opensocial.abortMigration` to the `rpc?aud=*` allowlist in `groupAdminScopes` and ensure the browser session requests it), keeping `aud` constrained to the verified target, and add a real (non-stubbed) GroupHost + FakeNetwork parity test for the expired-access-after-purge path.
