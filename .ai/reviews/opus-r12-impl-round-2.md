1. **Mid-CAS race test is sensitive to lease-heartbeat phase** — `apps/operator/src/operator/dm-multiprocess.test.ts:1079-1108`. The trigger barrier counts token-1 lease UPDATEs, but either hub's 4-second heartbeat (`dm-feed-wakes.ts:31,835-845`) can fire inside the short window between lease expiry (line 1069), token-1 restoration (line 1084), and the triggering webhook (line 1101). If realHub1's heartbeat lands before the restore it steps down and the `n === 2` assertion fails (a rare flaky CI failure, self-detecting); if a heartbeat consumes `n = 1` after the trigger is armed, the takeover lands at the entry CAS instead of the line-928 full-bucket CAS and the test passes with slightly weaker coverage. The window is tens of milliseconds against a 4-second period, so this is rare, test-only, and never a silent false pass of broken production code. A fix would pause both hubs' heartbeats (e.g., SIGSTOP realHub1's timer window or lengthen `HUB_LEASE_TTL_MS` for the fixture) while the trigger is armed.
