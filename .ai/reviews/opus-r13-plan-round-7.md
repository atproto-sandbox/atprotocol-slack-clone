## Medium

**M1. The `pending_approval` "denied" auto-exit cannot be computed by the client with the specified API surface.** plan:244 claims the `denied_or_cancelled_at` tombstone lets "client status probes distinguish moderator denial/cancellation from pending approval," and plan:270 deletes the journal entry "if denied (no `membership/<viewerDid>` and request no longer open / denied)." But the only probe plan:270 specifies is `authorizeSpaceSync` + `getRecord(membership/<viewerDid>)`, and for a non-member both "still pending" and "denied" produce the identical `400 SpaceNotFound` (plan:217's unauthorized branch; `members/self` has `publicRead: false`, plan:207). No specified surface carries the tombstone to the requester: upstream `requestJoin` output knows only `pending | admitted` (verified in `requestJoin.json`), `defs#joinRequest` has no status field, `listJoinRequests` requires a group-DID session (`proposal.md:224-226`), the `/group-admin/*` routes are group-session only (plan:151), and `pending_approval` is — correctly — forbidden from calling `requestJoin` again because plan:244's approval branch *upserts*, which would re-open a denied request. **Failure scenario:** an implementer resolves the unimplementable branch as "delete the entry when the probe fails" — then a still-pending entry is deleted; when the moderator later approves, `discoverCore()` skips the group (own-PDS `acceptance/self` → `RecordNotFound` → "skip without probing Group Host", plan:271), `acceptance/self` is never written, and the user is approved server-side yet never joins, silently. Gate 5's listed test ("cancelled/denied `pending_approval` entries never re-submit", plan:309) passes under that broken reading, so the gates don't catch it. **Fix:** make the exit rule implementable — either (a) drop the deny auto-exit: `pending_approval` exits only on observed admission (probe succeeds → write `acceptance/self`) or explicit local `cancelJoinRequest`, accepting a benign stale "pending" badge after a deny, and demote the tombstone to server-side upsert/audit state; or (b) specify a real probe surface (e.g., Group Host returns `status: "denied"` from `requestJoin` *without* re-queueing while a fresh tombstone exists — `knownValues` is open, so this is schema-valid; record the deviation in `protocol-authors-feedback.md`). Either way, add the missing Gate 5 case: *a `pending_approval` entry survives restart + `discover()` while still pending, and approval after that cycle still completes `acceptance/self`*.
