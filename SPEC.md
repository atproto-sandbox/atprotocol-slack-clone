# atproto Slack specification (Flock — R13 `opensocial.group`)

## Product

Build a Slack-style collaborative workspace on **`opensocial.group` atmospheric groups (`1 Group == 1 DID`)** and ATProto permissioned spaces (`com.atproto.space.*`), paired with person-scoped sovereign Direct Messages (`new.flock.dm.*`). Members author messages, reactions, Tasks operations, channel join requests, and bilateral `group.opensocial.acceptance/self` records in their own personal PDS repos. Group space policies (`group.opensocial.policy`) and role/membership records (`group.opensocial.role`, `group.opensocial.membership`) on the Group Host enforce group read/write/scope access, while personal PDS `com.atproto.memberspace.policy` member lists enforce DM access. Sessions, keys, and cached records stay in the browser; neither `apps/web`, `apps/operator`, nor `apps/group-host` stores DM rows in SQLite.

## V1 + R13 scope

- **Atmospheric `opensocial.group` workspaces (`1 Group == 1 DID`):**
  - Group creation via two-sided Group Host OAuth (`prompt=create` on `GROUP_HOST_URL`), minting a `did:plc:...` group account with `#atproto`, `#atproto_kem`, `rotationKeys`, `#atproto_pds`, optional public `group.opensocial.declaration/self` (`publicMeta`), core spaces `group.opensocial.meta/self` (`profile/self`, `rule/*`, `labeler/self`) and `group.opensocial.members/self` (`role/{admin,moderator,member}`, `membership/<creatorDid>`, host-maintained `space/*` modality index), and Flock modality spaces (`new.flock.workspace/self`, `new.flock.inbox/self`, `new.flock.channel/<skey>`).
  - Configurable `joinPolicy` (`"invite" | "approval" | "open"`), cross-PDS invitations written to `at://<inviteeDid>/space/group.opensocial.invites/self` (`group.opensocial.invite/<tid>`) with tracked `notifyRepoUpdate` delivery (`pending`/`delivered`/`failed` + retry) and real-time `inv1` push wakes (`new.flock.operator.getSpaceNotifyTarget`), shareable invite links, and self-service `requestJoin` / `cancelJoinRequest` / `leaveGroup`.
  - Flat union RBAC (`group.opensocial.policy` + `role/*` + `membership/*`), `assignable` anti-escalation, live `effectiveMemberPermissions` narrowing, `O(1)` membership writes across up to 100 channels, per-private-channel `channel-<skey>` roles (`unlisted: true`), and private-channel join requests (`new.flock.joinRequest` / `decideJoinRequest`) distinct from group-level join requests (`listJoinRequests` / `denyJoinRequest` / `decideGroupJoinRequest`).
  - ATProto-native in-space moderation: member `createReport`, moderator `listModSubjects` / `getModSubjectHistory` / `resolveModSubject`, and `<groupDid>`-authored `com.atproto.label.record` (`!takedown`, `!hide`, custom `labeler/self` values) projected by latest `cts` across client, reader, web, bot, and webhooks.
  - Incarnation-guarded 3-phase leave (`If-Match-Membership-Incarnation`), sole-member reversible deactivation + 4-phase reactivation, pre-tombstone zero-residue `deleteAccount`, sovereign PLC `rotationKeys` custody (`/group-admin/controller-session`), and two-GroupHost Standard & Coordinated v1 migration.
- **Messaging, apps & extensions:** Public and private channels, rich message blocks, one-level replies, per-author emoji reactions, message permalinks, non-roster app service principals (`apps/echo-bot`, `apps/webhooks` via `appRoleKey(appDid)` and `known_app_subject`), and the causal-DAG/HLC/OR-Set `new.flock.ext.tasks` extension.
- **Direct messages (`new.flock.dm.*`):** 1:1 and group conversations (2–100 participants) on personal PDS `com.atproto.memberspace.policy` spaces with zero server-side DM storage or gating (see "Direct-message invariants" below).
- **Independent app interoperability:** **Flock Desk** (`apps/desk` + `packages/shell`, `:3005`) provides a second, genuinely independent browser client using only published lexicons, personal-PDS OAuth (`deskMemberScopes()`), direct Group Host / writer-PDS reads via `@flock/reader`, and direct writes—with zero `@flock/client`, zero `@flock/web`, and zero `@flock/operator` dependencies—verified for canonical state, private roster, and moderation parity against `@flock/web` in `protocol-tests/browser/desk-parity.spec.ts` and `features/independent-app-and-launch.feature`. Standalone headless readers in `packages/reader` cover OpenSocial groups/channels (`independent.ts`), DMs (`independent-dm.ts`), and Tasks (`independent-tasks.ts`). Out of v1 scope: presence, voice/video calls, full-text server search, DM end-to-end encryption, or retroactive erasure of already-replicated client copies.

## Protocol & governance invariants

- **Lexicon inventory (`135` JSON files):** `36` `new.flock.*` modality/DM/operator schemas + `27` vendored `group.opensocial.*` schemas + `72` vendored `com.atproto.{space,memberspace,managedspace,personalspace,identity,label,repo,server,sync}.*` schemas (`99` upstream schemas verified by SHA-256 in `opensocial-lexicons.test.ts`; `63` public `new.flock.*` + `group.opensocial.*` schemas verified against live DNS TXT + XRPC by `pnpm verify:lexicons`).
- **Canonical authorization vs bilateral roster display:** Authorization (`effectiveMemberPermissions`, `isAdmin`, `isEffectiveAdminMember`, Operator capability checks, and space read/write enforcement) derives **strictly** from `<groupDid>`-authored `membership/<did>`, `role/*`, `group.opensocial.policy`, and `assignable` — never from personal-PDS `acceptance/self`. Bilateral pairing of `membership/<did>` + member-authored `group.opensocial.acceptance/self` (verified via `"new.flock.incarnation"` and post-ejection writer `repoRev`/`spaceRev` evidence) governs human `members` vs `pendingMembers` display and client discovery.
- **Reserved `<groupDid>` & non-roster app service principals:** `<groupDid>` has implicit self-membership and is rejected (`400 CannotTargetGroupSelf`) as an explicit `membership`, `app.install`, or personal-method target. Bots registered via `new.flock.app.install` are recorded permanently in `known_app_subject`, hold `[appRoleKey(appDid)]`, never write `acceptance/self`, and never count toward `effectiveHumanAdmins` or `LastAdmin`.
- **Writer eviction & credential bounds:** Losing `write` on any group space immediately evicts the writer (`removeWriter` + `#repoRemoved`). Removing read access blocks new credentials (`400 SpaceNotFound`); existing `Atproto-Space-Credential` tokens expire strictly at `exp` (`10 min` default, `3600 s` ceiling, zero grace skew) and are batch-revoked (`<= 100` JTIs via `notifyCredentialsRevoked`) on deactivation, sole-member leave, migration cutover, and deletion.
- **Journaled Operator mutations & demoted-actor recovery:** Operator mutations (`new.flock.operator.execute`) authenticate caller service JWTs (`aud = OPERATOR_SERVICE_REF`, `lxm`), re-verify live `role/*` + `membership/*` + `spacePolicies` before admission, before each step, and on crash recovery, and serialize per workspace (`PRIMARY KEY (workspace, actor, operation_id)`). If `ownerDid` (`operation.actor`) loses privileges mid-operation (`OPERATION_TAKEOVER_MIGRATION = 4`), `0`-step pending rows abort cleanly (`aborted_actor_revoked`) while `>=1`-step partial rows can be resumed to completion by a live effective human admin (`taken_over_by = executorActor.did`, audited via `operationAdminTakeover`).
- **Validation & record bounds:** Shape and semantic rules (`packages/protocol/src/{keys,registry}.ts`) enforce `isValidRecordKey` (`1..512` chars on protocol URIs/roles/`any` spaces; `1..128` `isSkey` on Flock-minted keys), exact `isTid` (`^[234567abcdefghij]...`), `literal:self` on singleton spaces/records, strict `"new.flock.*"` open-object extension types, `com.atproto.label.record` `tid` rkeys, non-empty `val`, and same-space targeting (`CrossSpaceLabel`), HTTP(S) `profile.url`, and `64 KiB` client record caps (`1 MB` XRPC JSON / `200`-write `applyWrites` caps on Group Host).

## Direct-message invariants

DMs belong to people, not groups or workspaces, and every invariant below is enforced by personal PDS `com.atproto.memberspace.policy` membership and record ownership (guarded mechanically by `no-legacy-memberspace` and `NO_DM_IMPORT` in `eslint.config.mjs`):

- **No shared authority or Group Host involvement.** Each participant owns `at://<did>/space/new.flock.dm.inbox/self` and their own conversation half `at://<did>/space/new.flock.dm.conversation/<convKey>`.
- **No server-held member session.** `DM_BROWSER_SCOPES` lives only in browser IndexedDB (`apps/web/src/browser/session.ts`) with non-extractable WebCrypto DPoP keys, disjoint from all Operator and Group Host scopes (`packages/protocol/src/scopes.test.ts`).
- **Zero DM SQLite rows.** Neither `apps/operator` nor `apps/group-host` stores any DM rows. Optional push wakes use `new.flock.operator.getDmNotifyTarget` (`SpaceCredential` + RFC 9421 PoP + `pop:<hmac>` replay lock → stateless `dm1` token → ephemeral in-memory `dm-feed-wakes.ts`), falling back immediately to un-notified `authorizeSpaceSync` if Operator is unavailable.
- **Independent-app parity.** `packages/reader/src/independent-dm.ts` reconstructs identical DM state from `new.flock.dm.*` lexicons alone without importing `packages/client/src/dm/**`.

## Acceptance envelope

- **Workspace/group envelope (`WORKSPACE_ENVELOPE`):** `200` members, `100` channels (`maxPrivateChannelsPerMember = 90`, `maxRolesPerMember = 100`, `maxPolicyGrantsPerSpace = 100`), `20` installed apps, and `20,000` messages per channel. Membership updates across a `100`-channel group execute in **`1` XRPC write (`<= 250 ms`)**; writer eviction across `100` spaces completes in `<= 500 ms`; Group Host emits **`1` webhook per message** to Operator at `200` members.
- **DM & sync budgets:** `100` DM participants and `20,000` messages per conversation; warm channel reopen uses `1` XRPC call (`p95 <= 150 ms`); browser warm reload `<= 12` XRPC calls and 1-message live wake `<= 6` XRPC calls (`<= 2,000 ms`).
