# Architecture

Flock builds collaborative workspaces on **Atmosphere Groups (`org.atgrp.*`, `1 Group == 1 DID`)** over ATProto permissioned spaces (`com.atproto.space.*`), alongside person-scoped, sovereign Direct Messages (`new.flock.dm.*`) hosted directly on each participant's personal PDS (`com.atproto.memberspace.policy`).

## Runtime boundaries

- **Browser client (`apps/web/src/browser`, `@flock/client`):**
  - **Personal PDS OAuth session (`apps/web/src/browser/session.ts`):** Authenticates the member at their personal PDS with one grant (`memberGrantScopes` in `packages/protocol/src/scopes.ts`: `DM_BROWSER_SCOPES` + spelled-out `ATGRP_PARTICIPATE_SCOPES` + Flock modality member scopes + `OPERATOR_METHODS`, including `getDmNotifyTarget` and `getSpaceNotifyTarget`). Tokens and non-extractable WebCrypto DPoP keys stay in browser IndexedDB.
  - **Per-user Group-DID OAuth sessions (`apps/web/src/browser/group-session.ts`, `GroupBrowserOAuthClient`, `packages/client/src/group-client.ts`):** Built directly on base `OAuthClient` (never `BrowserOAuthClient`, preventing `@atproto-oauth-client` storage/sub collisions) with an isolated IndexedDB database (`flock-group-oauth:${viewerDid}`, `DB_VERSION = 2`) and `navigator.locks` (`flock-group-lock:${viewerDid}:*`), served via `/oauth/group-client-metadata.json` and `/oauth/group-callback`. Used by moderators, profile editors, admins, and independent clients for direct browser-to-Group-Host moderation, join-request review, rules, profile edits, invites, reactivation, deletion step-up, and host migration.
  - **Client sync engine (`packages/client`):** Syncs spaces directly via `authorizeSpaceSync` into per-account IndexedDB (`SyncStore`, `DB_VERSION = 5`), writes member-authored records (`channel.message`, `channel.reaction`, `ext.tasks.*`, `joinRequest`, `app.command`, `app.action`, and `org.atgrp.confirmation/self`) to the member's own personal-PDS repo, provisions/reads `at:space/<viewerDid>/org.atgrp.inbox/self`, runs crash-safe `leavingGroups` (3-phase), `joiningGroups` (5-phase), and `reactivatingGroups` (4-phase) journals, and calls personal Group Host methods (`requestJoin`, `cancelJoinRequest`, `leaveGroup`, `org.atgrp.mod.{submitReport,submitAppeal,querySelfHistory}`) and Operator methods with service JWTs.
- **Next.js web server (`apps/web`):** Serves the React UI, per-request nonce CSP (`src/proxy.ts`), and static OAuth client metadata/callback pages (`/oauth/client-metadata.json`, `/oauth/callback`, `/oauth/group-client-metadata.json`, `/oauth/group-callback`). Holds **no database, no secret, no member session, and no member API routes**.
- **Reference Atmosphere Groups Group Host (`apps/group-host`, `:3004`):** Standalone Node/Express XRPC & OAuth 2.1 Authorization Server hosting Atmosphere Group DIDs (`did:plc:...`). Each group publishes `#atproto` (signing key), `#atproto_kem` (P-256 HPKE key), `rotationKeys`, and `#atproto_pds` (`AtprotoPersonalDataServer` pointing at `GROUP_HOST_URL`; Group Host's own `did:web` document also advertises `#atgrp_host` `AtgrpHost`). Hosts each group's signed `@atproto/repo` MST public repository (publishing empty `org.atgrp.declaration/self`), non-deletable core spaces `org.atgrp.meta/self` (`about/self`, `config/self`, `com.atproto.label.record`) and `org.atgrp.members/self` (`role/*`, `membership/*`, `rule/*`, `labeler/self`, member-authored `confirmation/self`, host-maintained `space/*` modality index, account `com.atproto.label.record`), Flock modality spaces (`new.flock.workspace/self`, `new.flock.inbox/self`, `new.flock.channel/<skey>`, `new.flock.app.inbox/<appSkey>`, `new.flock.ext.tasks/<tasksSkey>`), outbound cross-PDS `org.atgrp.invite/<tid>` repos, join-request & moderation/appeals queues, and two-GroupHost Standard & Coordinated v1 migration across **46 classified SQLite tables** (`SCHEMA_TABLE_CLASSIFICATION`: `42` `GROUP_PURGED_TABLES` + `1` `RETAINED_TOMBSTONE_TABLES` + `2` `GLOBAL_TTL_TABLES` + `1` `GLOBAL_TABLES`).
- **Flock Operator (`apps/operator`, `:3001`):** Standalone Node/Express XRPC & authority-flow server (`OPERATOR_URL`). Holds shared application OAuth sessions on `<groupDid>` (encrypted at rest with AES-256-GCM under `AUTH_ENCRYPTION_KEY`) to power: (a) 1-webhook-per-space `notify` registrations (`registrations.ts`) and the content-free `getChanges` cursor feed, (b) crash-safe multi-space modality orchestration (`createWorkspace`, `createChannel`, `transitionChannel`, `archiveChannel`, private-channel `decideJoinRequest`, group-admission `decideGroupJoinRequest`, `inviteMember`, `removeMember`, `setAdmin`, `leaveWorkspace`, `leaveChannel`, `reconcileWorkspace`, `installApp`, `updateAppAccess`, `uninstallApp`, `enableExtension`, `disableExtension`), and (c) stateless `dm1` (`getDmNotifyTarget`) and `inv1` (`getSpaceNotifyTarget`) push-wake webhook tokens. It never stores member sessions, message bodies, locally authoritative ACLs, or DM rows in SQLite.
- **Personal PDSes:** Hold each human or bot account's personal identity, their authored space records (`channel.message`, `channel.reaction`, `ext.tasks.*`, `joinRequest`, `confirmation/self`), their personal cross-PDS invitation inbox (`at:space/<userDid>/org.atgrp.inbox/self` governed by `com.atproto.memberspace.policy` `{ publicRead: false, publicWrite: true }` with zero members), and all sovereign Direct Message spaces (`new.flock.dm.inbox/self` and `new.flock.dm.conversation/<convKey>`).
- **Independent readers (`packages/reader`) & first-party apps (`apps/echo-bot`, `apps/webhooks`):** `@flock/reader` consumes only `@flock/protocol` and `@atproto/{space,star,lex-data,lexicon}` (never `@flock/client` or server databases) to prove zero lock-in across channels/groups (`independent.ts`), DMs (`independent-dm.ts`), and Tasks (`independent-tasks.ts`). `@flock/echo-bot` and `@flock/webhooks` run as non-roster app service principals (`appRoleKey(appDid)`) built solely on `@flock/client`.

## Atmosphere Groups governance & session modes

1. **Flat Union RBAC (`org.atgrp.policy`) & Live Narrowing (`effectiveMemberPermissions`):**
   - Group spaces use `org.atgrp.policy` (`{ publicRead, unlisted, grants: [{ role, read, write, permissions? }] }`), mirrored automatically at `com.atproto.space.policy/self`.
   - Every group-DID OAuth request, role/policy anti-escalation check, effective-admin check, and Operator capability check evaluates `effectiveMemberPermissions(state, groupDid, memberDid)` (`packages/protocol/src/scopes.ts`), unioning `expandGroupScopes` across assigned `role.permissions` with `expandPolicyGrantScopes` across every non-deleted space's matching `policy.grants[].permissions` (strictly clamped to that space).
   - Losing `write` on any space (via role edit, policy update, `removeMember`, or `leaveGroup`) atomically evicts the writer (`removeWriter` + `#repoRemoved`).
   - Private channels use a per-channel role `channel-<skey>` (`unlisted: true` policy); adding or removing a member across 100 public channels is an **`O(1)` single `putRecord(membership/<did>)` write** in `org.atgrp.members/self`.
   - Installed bots (`new.flock.app.install`) are tracked in Group Host's non-prunable `known_app_subject` ledger with deterministic role `appRoleKey(appDid)` (`"app-" + base32Lower(sha256(appDid)).slice(0, 52)`), excluded from human rosters and `LastAdmin` counts, and uninstalled cleanly in `RoleInUse`-safe order (strip policy grants → delete `membership` → delete `role` → mark `app.install.active = false`).

2. **Three Complementary Session Modes:**
   - **Per-user Group-DID OAuth (`GroupBrowserOAuthClient` / `GroupClient`):** Authenticates the acting human at their personal PDS via Group Host's upstream OAuth client (`/oauth/authorize` → `/oauth/upstream-callback` with per-flow `gh_oauth_*` CSRF cookie and isolated throwaway callback `Map` that calls `session.signOut()` immediately → mandatory `/oauth/confirm-action` downstream consent screen) and mints DPoP-bound `<groupDid>` tokens dynamically narrowed on every request to live `effectiveMemberPermissions` and `canAssign`.
   - **Shared Operator Application Session (`apps/operator`):** Authorized at group creation (`prompt=create` on `GROUP_HOST_URL`, 5-state crash-safe `group_creation_journal`) and reauthorizable by any live effective human admin. Every journaled operation (`OPERATION_TAKEOVER_MIGRATION = 4` / `ATGRP_MIGRATION = 6`) verifies live `role/*` + `membership/*` + `spacePolicies` before admission, before every step, and on crash recovery (never gating authorization on personal-PDS `confirmation/self`, which gates roster display and client discovery). If an operation's `ownerDid` (`operation.actor`) is demoted or ejected mid-flight: `leaveChannel` completes via `operationSatisfiedByState` if already satisfied; `0`-step pending rows transition terminally to `state = 'aborted_actor_revoked'` (`operationAbortedActorRevoked`); and `>=1`-step partial rows allow a live effective human admin holding `canAssign` coverage to resume under `takeoverBy` (`operation.taken_over_by = executorActor.did`, recording `operationAdminTakeover` and subsequent step events under `executorActor.did` while keeping `(workspace, ownerDid, operation_id)` immutable).
   - **Personal PDS & Service-Auth Calls:** Ordinary members use only their personal PDS session to read/write spaces, provision `inbox/self` (`WorkspaceClient.ensureInvitesSpace()`), register `inv1` push wakes (`new.flock.operator.getSpaceNotifyTarget`), write/delete `org.atgrp.confirmation/self`, and call `org.atgrp.{requestJoin,cancelJoinRequest,leaveGroup}` and `org.atgrp.mod.{submitReport,submitAppeal,querySelfHistory}` with service JWTs (`aud = "${groupDid}#atproto_pds"`).

3. **Bilateral Membership Pairing, Lifecycle Journals, Moderation & Host Migration:**
   - **Incarnation-guarded bilateral roster pairing:** Group Host stamps `"new.flock.incarnation"` (`crypto.randomUUID()` on absent→present `membership/<did>`, preserved across in-place role edits, with deterministic `"legacy-cid:" + cid` fallback for unannotated `space.importRepo` imports), `"new.flock.generation"`, `"new.flock.admittedSpaceRev"`, and `"new.flock.afterWriterRev"` onto `membership/<did>`. `WorkspaceSummary` pairs `<groupDid>`-authored `membership/<did>` with member-authored `confirmation/self` (strictly validating `"new.flock.*"` extensions and writer `repoRev`/`spaceRev` evidence so stale incarnations or future-dated pre-ejection `confirmation/self` records never appear in `members`; `membership`-only appears in `pendingMembers`).
   - **Client lifecycle state machines (`SyncStore`):**
     - `leavingGroups` (3 phases under per-`(viewerDid, groupDid)` lock): `"leaving_group"` calls `leaveGroup` with `If-Match-Membership-Incarnation` **before** touching own-PDS `confirmation/self` (so `400 LastAdmin` and `409 MembershipIncarnationMismatch` leave `confirmation/self` intact) → `"deleting_acceptance"` → `"reconciling_post_delete"` (restoring `confirmation/self` if concurrently readmitted on another device).
     - `joiningGroups` (5 active phases + passive user-action states across `create`, `open`, `invite`, `approval`): `"submitting"` (`Idempotency-Key: operationId`) → `"pending_approval"` (polled via durable-membership-first `GET /group-member/join-status`) → `"membership_verified"` → `"acceptance_pending"` → `"discovery_verified"`, plus passive `"orphaned_by_migration"`, `"expired_unknown"`, `"unsupported_status"`, and `"quota_exceeded"`.
     - `reactivatingGroups` (4 phases after sole-human-member `leaveGroup` reversible deactivation on Flock workspaces): `"activating"` (`recovery` OAuth `prompt=login` → `activateAccount`) → `"restoring_acceptance"` → `"reauthorizing_operator"` → `"refreshing_discovery"`. (Non-Flock Atmosphere Groups without `new.flock.workspace/self` stay `activated = 1` on sole-member leave when external sovereign PLC `rotationKeys` exist, manageable via `POST /group-admin/controller-session`.)
   - **Pre-tombstone zero-residue `deleteAccount` (`group_deletion_journal`):** `requestAccountDelete` + `/group-admin/claim-action-token` + `deleteAccount` drains `#spaceDeleted`, `100`-JTI-batched `notifyCredentialsRevoked`, and cleared-commit `notifyRepoUpdate` across `group_invite_target` **while `<groupDid>`'s PLC DID is still live**, tombstones PLC (`409`-only retry), and purges all `42` `GROUP_PURGED_TABLES` (`0` residual rows), paired with tombstone/takedown-aware invite consumer pruning.
   - **ATProto-native in-space moderation & appeals:** Members submit reports via `org.atgrp.mod.submitReport` (validating `<groupDid>` records in `space_record`, member/bot records via `space_writer`, and `<groupDid>` or member DIDs in `members/self`); moderators review `org.atgrp.mod.querySubjects` / `querySubjectHistory` / `updateSubject` and publish `<groupDid>`-authored `com.atproto.label.record` (`!takedown`, `!hide`, custom `labeler/self` values) inside the subject's space. Subjects (including former members who were ejected or penalized) can submit appeals (`org.atgrp.mod.submitAppeal`) and inspect their own moderation history (`org.atgrp.mod.querySelfHistory`). `packages/protocol/src/moderation.ts` projects latest-`cts` labels identically across `@flock/client`, `@flock/reader`, `apps/web`, `apps/desk`, `apps/echo-bot`, and `apps/webhooks` (withholding `!takedown` records at projection without breaking writer LtHash verification, and collapsing `!hide` behind a UI toggle).
   - **Two-GroupHost migration (`migration.ts`):** Supports v1-scoped Standard ATProto migration (zero-extension inbound from 1-key `org.atgrp.policy` hosts, Flock-Advertised outbound target capability negotiation via `#atgrp_host` or `capabilityProofJwt`, `#atproto`-signed `/group-admin/public-group-keys` across 1..5 keys, and `X-Group-Migration-Key-Provenance` JWS for unattested multi-key sources) plus Opt-In Coordinated v1 atomic cutover (`prepare-migration` RFC 8785 JCS manifest + `83`-byte `X-Group-Migration-Ticket` → `migration-manifest` → `createAccount` / CAR `importRepo` / `importSpaceMeta` / `space.importRepo` / `100 MiB` blob & stream caps → `migration-attestation` → `signPlcOperation` / `submitPlcOperation` preserving external sovereign `rotationKeys` and rejecting `SourceRotationKeyRetained` → `activateAccount` → `/group-admin/finalize-migrated-source`, with `new.flock.group.abortMigration` for clean abort before cutover).

## Sync, storage & protocol compatibility

- **Verified space sync (`packages/client/src/sync.ts`, `packages/protocol/src/atproto/space-credential-core.ts`):** Clients exchange a personal-PDS delegation token via `com.atproto.space.authorizeSpaceSync` (`credentialKey`, optional inline `notify`, returning `{ credential, spaceRev? }`) for a 10-minute key-bound `Atproto-Space-Credential`. Requests carry RFC 9421 signatures (`createSpaceSigHeaders`, `tag="atproto-space-credential"`) and request ephemeral HPKE KEM-MACs (`Accept-Signature`, `info: "atproto-mac"`) verified on `getRecord`, `getLatestCommit`, every page of `listRepoOps`, and streaming `getRepo` (`application/vnd.dasl.star`).
- **Bounded client & server storage:** Browser IndexedDB stores cached space records per viewer DID and drops spaces on lost read access or `#spaceDeleted` while preserving cached state across transient `RepoTakendown` / `RepoDeactivated` suspension on the space authority. Group Host (`./data/group-host.db`) and Operator (`./data/flock.db`) run WAL-mode SQLite with `0o600` owner-only permissions and bounded TTL/retention sweeps; online backups use `pnpm backup:db` and `pnpm backup:group-host` (`scripts/backup-db.mjs`).
- **Upstream pins & pre-launch lexicon gate:** Pinned to `bluesky-social/atproto#5187` @ `f839c47e6523a1a7adb367ef70513a3c6688c38b` + `protocol-tests/atproto/strict-credential-expiry.patch` (enforced cryptographically by `scripts/verify-pinned-checkout.mjs` across `19,251` dist artifacts; Group Host also enforces explicit zero-skew `nowSec >= payload.exp` in `verifyGroupSpaceCredential`) and `atmospheregroups.org/spec` @ `0885261c9cd1af80e89908571f926c2d0c71771f` (`104` upstream-vendored JSON schemas verified in `opensocial-lexicons.test.ts` alongside `37` `new.flock.*` schemas = `141` total JSON lexicons). Because public ATProto PDSes resolve every non-wildcard `space:<nsid>` token via `_lexicon.<authority>` DNS TXT → `com.atproto.lexicon.schema` during `OAuthProvider.authorize()`, production deployments must pass `pnpm verify:lexicons` (`scripts/verify-public-lexicons.mjs`) before serving public PDS accounts.

## Direct-message runtime boundary

DMs (`new.flock.dm.*`) remain person-scoped and sovereign on each participant's personal PDS (`com.atproto.memberspace.policy`), completely isolated from Group Host and Operator governance:

- **One personal browser OAuth session (`apps/web/src/browser/session.ts`):** `DM_BROWSER_SCOPES` is held only in browser IndexedDB with non-extractable WebCrypto DPoP keys and asserted disjoint from every Operator and Group Host server scope (`packages/protocol/src/scopes.test.ts`).
- **Isomorphic `DmClient` (`packages/client/src/dm/dm-client.ts`) & independent parity (`packages/reader/src/independent-dm.ts`):** Depends only on `@flock/protocol` (zero Node built-ins, zero Operator/Group-Host imports, enforced by `eslint.config.mjs` including `flockBoundariesPlugin`'s `no-legacy-memberspace` rule restricting `com.atproto.memberspace.{putMembers,removeMembers,listMembers}` to DM and protocol boundaries).
- **Zero DM rows in SQLite:** Neither `apps/operator` nor `apps/group-host` stores any DM rows. Optional push wakeups use `new.flock.operator.getDmNotifyTarget` (verified with `SpaceCredential` + RFC 9421 PoP + `pop:<hmac>` replay lock) to mint stateless 30-minute `dm1` HMAC tokens feeding Operator's in-memory `dm-feed-wakes.ts` ring (`0o600` Unix socket hub across local workers), falling back immediately to `authorizeSpaceSync` without `notify` if Operator is unreachable.
